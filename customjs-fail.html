Eighteen ways it breaks

Every card is a snippet that should fail a Custom-JS step, with the exact error it should produce. Run it here executes the same string in this page and reports what the browser actually did — so the page is the oracle, and anything the product reports differently is a finding.

Two of the eighteen are the point of this page: they raise no error at all and record a wrong outcome — marked passes wrongly. Two more the browser cannot decide on its own: whether they fail depends entirely on whether the executor awaits a Promise and enforces a step timeout.

This page grades strictly against that contract: a validation passes only on === true, a Create variable only on a non-empty string. Async returns, thrown-error reporting and JS timeouts are not documented for Custom JS — the async and timeout cards below are exactly the undocumented ground.

F · Breaks only on replay

reading flag…

Everything above is a snippet that fails now — which an agentic recorder cannot author, because its objective is a test that replays green. Ask it to add a failing step and it will rewrite the snippet into a passing validation, skip the step, or run the snippet as a probe and never record it. The run comes back green either way.

These four hooks solve that. While the flag is healthy each returns a clean value, so the agent records an honest passing step. Flip the shared flag and the same saved snippet fails on replay — a genuine Custom-JS step failure reached through the normal record-then-replay lifecycle, with no agent asked to author a failure.
